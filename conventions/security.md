# Security and privacy

Contest Keeper watches contestants, so it must be careful with what it collects and trustworthy in what it reports.

## Never

- Store, log or send passwords, cookies, session ids or tokens of contestants.
- Commit secrets. Use `.env` files (ignored by Git) locally and GitHub secrets / the server's secret store elsewhere.
- Put secrets or personal data in URLs, query strings, error messages or panic messages.
- Turn off TLS checks, even "just for testing". Use a local CA instead.

## Personal data

- Collect the minimum: stick id, platform username, times, submission fingerprints.
- Recordings stay on the stick unless the organizer turns upload on.
- Logs show usernames only at `debug` level, and never in public bug reports.

## Keys and signing

- Every stick has its own key. Keys are generated by Forge, never reused between contests.
- Compare signatures and tokens in constant time.
- Use well-known crates (`ring`, `ed25519-dalek`, `hmac`, `sha2`, `argon2`), never home-made crypto.

## Input

- Everything from the network, the stick or a platform is untrusted until parsed into checked types.
- Limit sizes (request bodies, uploads, JSON depth) and rates.

## Dependencies

- `cargo deny` checks licenses and known vulnerabilities on every PR; Dependabot opens update PRs.
- Lock files are committed. GitHub Actions are pinned to a major version and updated by Dependabot.

## Reporting

Security problems are reported privately, see [SECURITY.md](../SECURITY.md).
